## 使用入口

另备安装 `lerobot==0.4.4` 的 Python 环境；仿真、规划和模型环境按 [安装说明](INSTALL.md) 配置。候选目录应包含四种基础物体的既有候选。

```bash
bash run.sh pipeline --output /absolute/new-directory --gpus 0,1,2,3 --workers 3 \
  --arm-speed-profile baseline --execution-profile baseline --candidate-root /absolute/candidates \
  --lerobot-python /path/to/lerobot/python
```

该历史验收每物体 5 个固定槽，baseline 速度、symmetry off，随后严格筛选、导出、完整读回和 100 步 ACT 检查。复现该速度时需显式传 `--arm-speed-profile baseline`；2026-11-16 起新 `pipeline` 默认采用已有 `recommended` 提速档位。入口先冻结本次源码，全部阶段从副本运行；各阶段日志和 `PIPELINE.json` 保留在输出目录。执行失败会停止并保存原因；这次显存故障的恢复使用了专门的恢复脚本，后续主入口的通用恢复见 [恢复说明](RECOVERY.md)。

仅导出已完成且启用了数据校验的批次可使用 `bash run.sh export --help`。默认要求静止和完整稳持证据；`--allow-legacy-unverified` 只供历史格式调试，无法通过新训练检查。

## 验收边界与证据

原批次发生过一次 Vulkan/RTX 初始化显存耗尽，未进入规划或执行。保留故障现场后，用相同源码、候选、初态和种子恢复未执行槽位，最终完成原计划 20 槽；基础设施重启一次，物理抓取重试零次。结果证明经资源恢复后的链路完成，尚未证明无人干预故障恢复能力。

两条开发记录独立于固定批次。第二条因采集中修改主目录而产生源码快照不一致，校验正确拒绝；正式批次使用未变化的 104 文件源码快照。主入口随后加入自动源码冻结及相应回归测试。

全量历史审计曾发现 27 条旧成功记录只有 119/120 步稳持证据；本批使用统一评分和停止时机，20 条均有完整证据。这不追溯补齐旧数据。验收范围限四种已知网格和固定的小范围初态；短训练检查验证数据消费和训练流程，不提供闭环策略成功率结论。

2026-11-15 另发现原导出遗漏了此前 LeRobot 0.4.4 的统计修正：uint8 图像平方溢出，float32 数值矩也有消减误差。新导出先按真实存储 dtype 量化，再用 float64 中心化均值/总体标准差；保留官方图像抽样、5000-bin 近似分位数和 count 约定。官方读回现在同时从实际 Parquet 独立复算全部逐回合及全局统计，使用数值 `fsum` 与 RGB 整数频次检查，旧包会被拒绝。

修正版复用原始 20 条轨迹，位于证据根目录下 `acceptance/export_corrected_20261115/`；其读回及重新训练回执分别位于该目录的 `AUDIT.json` 和 `acceptance/training_corrected_20261115/RESULT.json`。原 `acceptance/export/` 与 `acceptance/training/` 保留作历史证据，原统计和归一化结论由修正版取代。物理成功的 20 条原始记录未变。

本地工作区证据根目录为 `../results/graspgen_pipeline_acceptance_20261113_01/`（相对仓库根目录，实验数据不随源码分发）。主要文件为 `REPORT.md`、`RESULT.json`、`ARTIFACT_SHA256.json`、`FINAL_VERIFICATION.json` 和 `CLOSURE_PIPELINE.json`。原始失败回执和 `acceptance/completed_slots/SOURCE_LEDGER.json` 保留了恢复来源。
